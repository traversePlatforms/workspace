# Outbox automations mock for Peak (24 Nov 2026)

A clickable mock of Outbox as Peak Pickleball's member-email automation tool, in place of Patch Retention. Matthew's own product (Outbox), with Peak as the client workspace inside it. For Matthew to review first. **Nothing in it sends, saves or reads real data.** Every screen carries the banner "Mock: nothing here sends. Sample data."

- **Private URL:** https://traverseplatforms.com/outbox-automations-mock-d34874/ (the folder name is also in `server/folder-name.txt`). The sign-in code is only in `~/.ssh/outbox-mock-code.txt` (0600), never in git or chat; the server keeps its sha256 (`'om|' . code`) only.
- **Server:** the same pattern as the Peak website mock. `public_html/outbox-automations-mock-d34874/` holds `index.php` (= `server/gate.php`) and `.htaccess` (= `server/htaccess.txt`). The files sit outside public_html in `~/www/traverseplatforms.com/outbox-automations-mock-private/site/` (0700/0600), with `config.php` (the hash) and `data/` (sessions, attempts). 10 wrong codes per IP per 15 minutes; byte ranges served.
- **No indexing:** noindex meta on the page, `X-Robots-Tag` from the gate and `.htaccess`, and `Disallow: /outbox-automations-mock-` in robots.txt (the prefix only). Backup of robots.txt before the change: `~/upload-backups/robots.before-outbox-mock-20261124.txt` (on the server and on the VM).
- **To update:** edit `site/`, then `tar -C site -cf - . | bash ~/jarvis/bin/sg.sh trav 'cd ~/www/traverseplatforms.com/outbox-automations-mock-private/site && tar -xf -'`. **To take it down:** delete both folders on the server and the robots line.

## Screens (hash routes in one page, `site/app.js`)

1. **Automations** (`#/automations`): one line of intro and one compact numbers row (Sent, Clicked, Joined, Opt-outs, Bounces; Opened small, with the Apple Mail note). 8 columns by default: Name (trigger under it), Status (on/off toggle + status pill), Last run, Next run, Sent, Clicked (count and %), Joined, Opt-outs. A Columns chooser adds Channels, Type, Delivered, Opened, Replies, Bounces, Failed. Filters: Status, Type, search. Fits 1440 px with no sideways scroll. Phone (under 760 px): the list comes first below the tabs, as compact cards (name, trigger, toggle, status, sent, clicked, joined), with the 30-day numbers in a collapsed "Last 30 days" strip below.
2. **Drawer** (`#/automations/<id>[/flow|/stats]`): on/off, trigger, channels (Email; texts later), type, whether it counts toward the sending cap, How it works (WHEN / WHO / THEN / EXIT), then Messages, Flow and Stats. Stats opens with a funnel: for the free class 78 reminded → 60 attended → 52 got the follow-up → 11 joined within 7 days (77%, 87%, 21%; 14% overall); sent → delivered → clicked for the others.
3. **Block editor** (`#/edit/<id>/<step>[/light|/full]`): subject and preview text; blocks (Text with Paragraph/Heading, Image, Button, Divider, Spacer), each can be added, removed, moved up or down, or dragged by its handle; merge-field chips ({first_name}, {class_time}) with a fallback each ("there", "your booked time"); a locked Brand kit panel ("Every email stays on-brand automatically"); Light / Full as two layouts of the same blocks; Phone / Desktop preview; Preview as one of 4 made-up people (one with no first name, one with no class); Test to me / Test to Cammie (toasts only). Beside the preview, **Inbox checks** that update as you type: images vs text, number of links, unsubscribe (locked footer), subject length, [brackets] left (these block Approve), and the "Likely: Primary inbox / Promotions" note. The approval box keeps Draft → Waiting for approval → Approved → Running and notes that Cammie gets an email when something waits (mock: none sent).
4. **Approvals** (`#/approvals`): each waiting email shows who sent it and when, "what changed since the last approval" as before/after lines (the Google review email has an approved 22 Nov version to compare), the history (who approved and when), a comment thread (sample comments), the Cammie-gets-an-email note, and Approve / Ask for changes (needs a comment). Approve stays disabled while [brackets] remain. Below: approved, not switched on, with who approved and when.
5. **Results** (`#/results`): the numbers row, the free-class funnel, by automation with a mini funnel per row, and the line against Patch.
6. **Settings** (`#/settings`): **Sending rules**: at most 3 emails per person in 7 days across all automations, service emails exempt (toggle; class reminders, failed payment, annual renewal, event reminder), over-the-cap handling [Cammie to choose]; quiet hours 8 pm to 7 am MT, queued emails go at 7 am. Then sending domain (SPF / DKIM / DMARC, example), unsubscribes from Patch, CourtReserve connection, people and texts, and the brand kit.
